# Windows MCP 启动耗时记录

测量日期：2026-10-16。环境：Windows、uv 0.10.8、Python 3.11；MCP SDK 2.3.0、xsdata 26.2、Pydantic 2.14.1。时间使用 `time.perf_counter()`，从客户端启动 uv 子进程前开始，到 `initialize()` 和 `list_tools()` 均完成为止，不含测量客户端自身的 Python 导入时间。所有成功样本均列出 13 个工具。

## 用户命令与发行包基线

在仓库外运行，使用正常 uv 缓存，未指定 schema 版本：

```powershell
uv run --python 3.11 -i https://pypi.tuna.tsinghua.edu.cn/simple --with "k3q-arxml[mcp]==2.1.3" -m k3q_arxml mcp
```

| 样本 | 握手完成 | 工具列表返回 |
| --- | ---: | ---: |
| 1 | 4.356 秒 | 4.362 秒 |
| 2 | 4.428 秒 | 4.434 秒 |
| 3 | 4.295 秒 | 4.300 秒 |

这组数据使用默认 4.2.2 绑定和已经下载的依赖，不代表首次安装，也不代表指定其他绑定后的启动耗时。

额外使用独立的空包缓存测量首次启动，复用本机已经安装的 Python 3.11，不清理正常使用的缓存：

| 自启动起的时间 | 事件 |
| --- | --- |
| 19.216 秒 | 第一条大包下载提示（lxml） |
| 21.449 秒 | 开始下载 k3q-arxml，15.9 MiB |
| 40.924 秒 | k3q-arxml 下载完成 |
| 42.184 秒 | 39 个包安装完成，安装本身耗时 1.25 秒 |
| 51.719 秒 | 握手完成并返回工具列表 |

下载提示之前还包含解释器发现、索引查询、依赖解析及小包准备，未对这些子阶段逐一计时。该独立缓存再次启动实测 9.553 秒；空载 uv（相同依赖参数，只执行 Python 打印）约 0.91 秒。因此 4 秒多是正常缓存下的一组实测结果，不能作为所有缓存、磁盘与网络状态下的启动保证。

## 耗时主要在哪里

对发行包分段导入的一个样本：

| 步骤 | 耗时 |
| --- | ---: |
| 导入 k3q_arxml 及其依赖 | 2.272 秒 |
| 其中：导入 AUTOSAR 绑定，使用独立 importtime 样本 | 1.570 秒 |
| 导入 CLI | 0.027 秒 |
| 导入 MCP SDK、模型和服务适配层 | 0.924 秒 |
| 创建服务并编译 XSD | 0.206 秒 |
| 创建完整 MCP 服务，包括上述 XSD 编译和工具注册 | 0.240 秒 |

“其中”和“包括”行不能重复相加。Python 导入分析显示绑定需要构造数千个 dataclass；即使有 `.pyc`，运行时仍须创建这些类型。工具列表传输本身约为 5～7 毫秒。

对原临时包流程的一次分段取样显示，复制包和 Skill 合计约 0.304 秒，校验及解压绑定约 0.040 秒，子进程加载目标绑定和包约 3.794 秒，子进程导入 MCP SDK 约 1.077 秒。主要成本是重复加载类型和临时包首次导入，解压本身只占很小一部分。

## 当前源码的修改与对比

按用户要求，指定其他版本时直接用校验过的 ZIP 原子替换当前库的 `autosar.py`，不再复制包。首次切换后仍通过新 Python 进程加载新类型；后续相同版本启动复用库文件与字节码缓存，不再解压或启动子进程。父进程不导入 MCP SDK。XSD 延后至首次加载工程时编译，后续校验复用；这个调整将约 0.2 秒的工作移至首次加载工程，不取消 XSD 校验。

源码对比使用同一开发环境的 `uv run --no-sync python -m k3q_arxml mcp`，以避免把依赖同步算入代码改动的收益。真实版本覆盖在测试包副本中进行，仓库默认绑定保持 4.2.2。下表全部计时到工具列表返回：

| 场景 | 样本 | 中位数 |
| --- | --- | ---: |
| 修改前，默认绑定 | 3.911、4.048、3.701 秒 | 3.911 秒 |
| 修改后，默认绑定 | 3.605、3.537、3.731 秒 | 3.605 秒 |
| 修改前，每次用临时包选择 00044 | 10.859、12.709、10.983 秒 | 10.983 秒 |
| 修改后，首次直接覆盖为 00044 | 8.420 秒，单次测量 | — |
| 修改后，再次启动相同的 00044 | 5.557、4.733、4.942 秒 | 4.942 秒 |

首次直接覆盖的单次样本不用于计算稳定加速比。默认绑定的中位数约减少 8%；相同 00044 版本再次启动的中位数约减少 55%。不同版本生成的类型数量不同，不能用默认绑定的时间替代 00044 的时间。

直接覆盖会改变当前环境后续进程使用的绑定，需要多个版本时分别使用独立环境。当前源码修改尚未发布，`--with "k3q-arxml[mcp]==2.1.3"` 仍运行原发行包。

## Windows 中文路径复现

原命令在中文路径的仓库根目录运行时，还复现了 Python 3.11 读取 uv 叠加环境 `.pth` 文件的 GBK 解码错误，在项目代码执行前就退出；uv 的索引参数同时会更新当前项目的锁文件索引。仓库外的发行包测量不触发这个错误。源码对比使用不叠加 `--with` 的开发环境，并设置 `PYTHONUTF8=1`。测量引起的锁文件索引变化已恢复，没有变更项目依赖。

## 验证范围

回归覆盖绑定校验失败保留原文件、原子替换失败后的清理、所选绑定的新进程加载、真实 stdio 工具调用与编辑保存、相同版本重新连接不再替换文件，以及首次加载工程时仍执行并复用 XSD 校验。测试只改动临时模型和库副本。
